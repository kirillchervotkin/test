# Города и команды

`001-create-cities-teams.sql` добавляет справочники в YDB без FOREIGN KEY.
Это исходная числовая схема; актуальная схема UUID описана в миграции 002 ниже.

```sh
node --env-file=.env scripts/references-migrate.mjs          # проверить таблицы
node --env-file=.env scripts/references-migrate.mjs --apply  # создать отсутствующую схему
```

Если таблицы уже существуют, скрипт показывает схему и отказывается менять её.
При частичном применении проверьте созданную таблицу и примените только оставшийся
CREATE TABLE. Скрипт ничего не удаляет и не перезаписывает.

Перед первым переходом с in-memory сохраните GET /cities и GET /teams работающего
старого процесса. Если там есть записи, импортируйте их с исходными ID до запуска
нового сервера. При этом переходе оба списка были пусты.

Сервисы используют DTO → service → repository → mapper. Общий SQL-репозиторий
календаря предоставляет одну serializable-транзакцию для справочников и ссылок.
Проверки дубликатов, города команды и удалений выполняются внутри неё.
Название города уникально без учёта регистра; имя команды уникально внутри города.
Удаление запрещено при ссылках из команд, матчей, слотов, сетки и шаблонов.
Создание/изменение шаблонов также проверяет существование ссылок.

Проверка на локальном сервере создаёт временные сущности:

```sh
node --env-file=.env scripts/references-check.mjs create /tmp/reference-check.json
# перезапустить локальный сервер
node --env-file=.env scripts/references-check.mjs verify-cleanup /tmp/reference-check.json
```

Данные теста удаляются по сохранённым ID только после проверки перезапуска.

## UUID (миграция 002)

Актуальный контракт: `cities.id`, `teams.id`, `teams.cityId` — строки UUID v4;
тип YDB — `Uuid`, как у остальных UUID-сущностей проекта. Ссылки календаря
`matches.cityId/homeTeamId/awayTeamId`, `tournament_team_slots.teamId`,
`bracket_slots.resolvedTeamId` также `Uuid`. Собственные ID турниров, этапов,
матчей, слотов и шаблонов остаются строками Uint64.

Миграция 001 выше описывает исходную схему. После неё применяется 002:

```sh
node --env-file=.env scripts/references-uuid-migrate.mjs
# остановить все процессы, которые пишут в эти таблицы
node --env-file=.env scripts/references-uuid-migrate.mjs --apply --writers-stopped
```

Скрипт применим только к пустым справочникам и календарю, включая этапы и JSON
шаблонов. При данных он отказывается от изменений: потребуется отдельное
преобразование ID и всех ссылок. Скрипт сначала создаёт и проверяет новые таблицы,
потом одним RenameTables переключает их, сохраняя старые как
`*_before_uuid_v2`. Повторный запуск проверяет уже применённую схему.
Не удаляйте резервные таблицы и не откатывайте их поверх новых данных.

Ограничения DTO описаны через `@Constraint`, включая Update DTO.
Репозитории выбрасывают `DbUniqueViolationException` и
`DbForeignKeyViolationException`; глобальный `DbConstraintExceptionFilter`
обрабатывает в том числе вложенные `cause` от SDK. Контракт ошибок:
дубликат — 409, отсутствующая ссылка — 422, удаление используемой записи — 409,
не найден сам объект запроса — 404. Ошибки ограничений имеют Content-Type
`application/problem+json`; `invalid_params` содержит поля, коды и переводы.
Уникальность названий и ссылочная целостность проверяются в serializable
транзакциях; FOREIGN KEY в DDL не добавляются. Ошибки уникальности YDB при INSERT
дополнительно преобразуются в кастомное исключение, прочие ошибки не маскируются.
